— Phase 1: Research หาข่าว —
1
Prism ค้นหาข่าว AI ล่าสุด
🔮 Prism
จุดเริ่มต้นของทุกโพส — Prism ค้นหาข่าว AI แล้วเลือกหัวข้อที่ตรง scope ของเพจ
📥 INPUT — ได้มาจากไหน
  • ตาราง เช้า/กลางวัน/เย็น
    ← มาจาก content-guidelines.md
  • scope เพจ
    ← มาจาก content-guidelines.md ของเพจนั้น
  • คำค้น "AI news today 2026"
    ← Prism กำหนดเองตามข่าวร้อน
⚙️ PROCESS — ทำอะไร
  • ใช้ WebSearch ค้นทั้งไทย+อังกฤษ
  • อ่านผลลัพธ์ เลือกหัวข้อเด่น 3-5 อัน
  • เทียบกับ scope → เลือกเพจเป้าหมาย
📤 OUTPUT — เอาไปใช้ที่ไหน
  • หัวข้อข่าว 3-5 อัน + URLs
    → ส่งไป Step 2 เป็น source ให้ NotebookLM
  • เพจเป้าหมาย (เช่น Prism Chronicle)
    → กำหนด tone + scope ของ draft
  • keyword สำหรับ research
    → ส่งไป Step 2 ใช้กับ add-research
↓หัวข้อ + URLs + keyword → Step 2
2
NotebookLM Research + รวบรวม Sources
📘 NotebookLM
รวบรวมข้อมูลจากหลายแหล่งเข้า Notebook เดียว — NotebookLM จะ index ทุก source ให้พร้อมใช้สร้าง content
📥 INPUT — ได้มาจากไหน
  • URLs ข่าว 3-5 อัน
    ← จาก Step 1 (WebSearch ค้นมา)
  • keyword เช่น "Gemini Spark Agentic"
    ← จาก Step 1 (Prism เลือก)
⚙️ PROCESS — ทำอะไร
  • notebooklm create สร้าง Notebook ใหม่
  • source add เพิ่ม URLs เป็น source
  • source add-research ค้นเพิ่มอัตโนมัติ
  • NotebookLM index ทุก source (30-60 วินาที)
📤 OUTPUT — เอาไปใช้ที่ไหน
  • Notebook ID
    → ใช้ใน Step 3, 4 เพื่ออ้างอิง Notebook
  • Sources 10-15 อัน (indexed แล้ว)
    → Step 3 ใช้สร้างบทความ
    → Step 4 ใช้สร้าง media
↓Notebook (sources indexed) → Step 3 + 4
— Phase 2: สร้างเนื้อหา —
3
NotebookLM สร้างบทความ Draft
📘 NotebookLM
ให้ NotebookLM สรุป sources ทั้งหมดเป็นบทความภาษาไทย — คนทั่วไปอ่านเข้าใจ นำไปใช้ได้จริง
📥 INPUT — ได้มาจากไหน
  • Notebook + Sources
    ← จาก Step 2 (indexed แล้ว)
  • Prompt สั่งเขียนบทความ
    ← Prism เขียน กำหนด: ≥3,000 ตัวอักษร, ภาษาไทย, คนทั่วไปเข้าใจ, มีสิ่งที่ลองทำได้
  • กฎ ต้องบอกว่า "สร้างโดย Prism"
    ← จาก content-guidelines.md
⚙️ PROCESS — ทำอะไร
  • notebooklm ask "สรุปเป็นบทความ..."
  • NotebookLM อ่าน sources ทั้งหมด → สรุปเป็นบทความ
  • Prism save เป็นไฟล์ .md ใน drafts/
📤 OUTPUT — เอาไปใช้ที่ไหน
  • บทความ draft ~6,000 ตัวอักษร
    → Step 5 ใช้ verify ข้อเท็จจริง
    → Step 6 ส่ง Origin review
    → Step 7 แสดง Master J
  • ไฟล์ drafts/YYYY-MM-DD_*.md
    → Step 9 ย้ายไป posted/ หลังโพส
↓Draft บทความ (.md) → Step 4, 5, 6, 7
4
NotebookLM สร้าง Media
📘 NotebookLM + ⭐ Origin
สร้าง infographic + podcast จาก sources เดียวกัน — ทุกชิ้นต้องสอดคล้องกับบทความ
📥 INPUT — ได้มาจากไหน
  • Notebook เดียวกับ Step 2-3
    ← ใช้ sources ชุดเดียวกัน เพื่อให้เนื้อหาสอดคล้อง
  • Style kawaii / professional
    ← จาก content-guidelines.md + brand voice
  • Image Request (ถ้าขอ Origin)
    ← Prism เขียน Subject/Style/Size/Use
⚙️ PROCESS — ทำอะไร
  • generate infographic (5-15 นาที)
  • generate audio podcast (10-20 นาที)
  • หรือ Origin สร้างรูปด้วย Codex DALL-E (2-5 นาที ส่ง SCP)
  • Download ไฟล์มาเก็บใน media/
📤 OUTPUT — เอาไปใช้ที่ไหน
  • Infographic .png
    → Step 5 เช็คสอดคล้องกับ text
    → Step 7 แสดง Master J
    → Step 8 แนบรูปตอนโพส
  • Podcast .mp3
    → เผยแพร่คู่กับโพส หรือโพสแยก
  • ไฟล์ media/YYYY-MM-DD_*
↓Draft + Infographic + Podcast → Step 5
— Phase 3: ตรวจสอบ —
5
Prism Verify ข้อเท็จจริง
🔮 Prism
Cross-check ทุกข้อมูลข้ามแหล่ง — ชื่อ product ถูกไหม ตัวเลขถูกไหม text กับ infographic ตรงกันไหม
📥 INPUT — ได้มาจากไหน
  • Draft บทความ
    ← จาก Step 3 (NotebookLM สร้าง)
  • Infographic
    ← จาก Step 4 (ต้องตรงกับ text)
  • ชื่อ product/ตัวเลข ที่ต้อง verify
    ← อ่านจาก draft แล้วสกัดออกมา
⚙️ PROCESS — ทำอะไร
  • WebSearch ค้นชื่อ product ทีละอัน
  • เทียบตัวเลข/วันที่ กับ official sources
  • เช็คว่า infographic ข้อมูลตรงกับ text
  • เพิ่ม source URLs ท้ายบทความ
  • เพิ่ม hashtag 5-8 อัน
📤 OUTPUT — เอาไปใช้ที่ไหน
  • Draft ที่ verify + แก้แล้ว
    → Step 6 ส่ง Origin review
  • Source URLs ท้ายบทความ
    → ติดไปกับ draft ตลอด
  • Hashtag 5-8 อัน
    → ใส่ใน caption ตอนโพส Step 8
↓Draft (verified) → Step 6
6a
Nexus Relay → ส่ง Draft ไป Origin
🌿 Nexus
Prism ส่งตรงไป Origin ไม่ได้ (federation auth) ต้องผ่าน Nexus เป็นตัวกลาง relay
📥 INPUT — ได้มาจากไหน
  • ข้อความ + path ไฟล์ draft
    ← Prism เขียนคำขอ review
  • maw API endpoint
    ← localhost:3456 (Nexus maw server)
⚙️ PROCESS — ทำอะไร
  • Prism: curl POST localhost:3456/api/send
  • target: "nexus" → Nexus รับแล้ว relay ต่อไป Origin
  • Origin อ่าน draft จาก shared filesystem
📤 OUTPUT — เอาไปใช้ที่ไหน
  • ข้อความถึง Origin
    → Origin เริ่ม Codex review (Step 6b)
↓ข้อความ relay → Origin
6b
Origin Codex Review (GPT-5.5)
⭐ Origin
Origin ใช้ Codex (GPT-5.5) อ่านบทความแล้วตรวจ 3 จุด: ข้อเท็จจริง, ข้อมูลบิดเบือน, ทำให้เข้าใจผิด
📥 INPUT — ได้มาจากไหน
  • Draft บทความ
    ← จาก Step 5 ผ่าน Nexus relay (Step 6a)
  • คำขอ review 3 จุด
    ← Prism กำหนดว่าต้องเช็คอะไร
⚙️ PROCESS — ทำอะไร
  • Codex อ่านทั้งบทความ
  • เช็คข้อเท็จจริง vs ความรู้ของ GPT-5.5
  • เขียน review report: ❌ ต้องแก้ / ✅ ถูกต้อง
  • ส่งผลกลับมาเป็นไฟล์ .md
📤 OUTPUT — เอาไปใช้ที่ไหน
  • Review report
    → เก็บที่ ψ/inbox/from-nexus/
    → Prism อ่านแล้วแก้ Draft → Draft v2
  • Draft v2 (แก้ตาม review)
    → Step 7 แสดง Master J อนุมัติ
↓Draft v2 + Review report → Step 7
— Phase 4: อนุมัติ —
7
Master J อนุมัติ
👑 Master J
ด่านสุดท้ายก่อนโพส — Master J ตรวจทุกอย่างแล้วตัดสินใจ
📥 INPUT — ได้มาจากไหน
  • Draft v2 (แก้ตาม review แล้ว)
    ← จาก Step 6b (Prism แก้แล้ว)
  • Infographic
    ← จาก Step 4 (NotebookLM สร้าง)
  • Codex review report สรุป
    ← จาก Step 6b (จุดที่แก้แล้ว)
  • จำนวนตัวอักษร
    ← Prism นับให้
⚙️ PROCESS — ทำอะไร
  • Master J อ่าน draft + ดูรูป
  • ตรวจว่าเนื้อหาเหมาะสม ถูกต้อง
  • ตัดสินใจ: อนุมัติ / แก้ไข / ไม่โพส
📤 OUTPUT — เอาไปใช้ที่ไหน
  • ✅ "อนุมัติโพสได้เลย"
    → Step 8 โพสทันที
  • ✏️ "แก้ตรงนี้..."
    → กลับ Step 3 หรือ 5 แก้ draft
  • ❌ "ไม่โพส"
    → จบ flow, เก็บ draft ไว้ใน drafts/
↓✅ อนุมัติ → Step 8
— Phase 5: เผยแพร่ —
8
โพสผ่าน Facebook Graph API
📘 Facebook
อัพโหลดรูป + สร้างโพสบนเพจ Facebook — ใช้ Graph API v25.0
📥 INPUT — ได้มาจากไหน
  • Draft v2 (approved) = caption
    ← จาก Step 7 (Master J อนุมัติ)
  • Infographic .png = รูปแนบ
    ← จาก Step 4 อยู่ที่ media/
  • Page token
    ← จาก config/platforms.json (permanent token)
  • Page ID
    ← จาก config/platforms.json → pages
⚙️ PROCESS — ทำอะไร
  • 1. POST /{page_id}/photos upload รูป (unpublished)
  • 2. POST /{page_id}/feed สร้างโพส + แนบรูป
  • Facebook API return Post ID + Photo ID
📤 OUTPUT — เอาไปใช้ที่ไหน
  • Post ID (เช่น 1184469..._122099...)
    → Step 9 บันทึกใน daily log
    → Step 10 ใช้ track engagement
  • โพสบน Facebook
    → ผู้ติดตามเห็นทันที
↓Post ID → Step 9 + 10
— Phase 6: บันทึก + ติดตาม —
9
Prism บันทึก Daily Log
🔮 Prism
บันทึกทุกอย่างเป็นประวัติ — ย้าย draft ไป posted เพื่อบอกว่าโพสแล้ว
📥 INPUT — ได้มาจากไหน
  • Post ID
    ← จาก Step 8 (Facebook return)
  • Draft v2 file
    ← จาก drafts/
  • เหตุผลที่โพส
    ← Prism เขียน (ทำไมเลือกหัวข้อนี้)
  • Source URLs
    ← จาก Step 5 (ท้ายบทความ)
⚙️ PROCESS — ทำอะไร
  • เขียน entry ใน daily log .md
  • ย้ายไฟล์ drafts/ → posted/
  • บันทึก: Post ID, สรุป, เหตุผล, sources
📤 OUTPUT — เอาไปใช้ที่ไหน
  • Daily log logs/YYYY-MM-DD.md
    → อ้างอิงในอนาคต ดูว่าวันไหนทำอะไร
  • Posted file posted/
    → เก็บเป็นคลัง content ที่โพสแล้ว
↓Log บันทึกแล้ว → Step 10
10
Assis_Bot ติดตาม Engagement
🤖 Assis_Bot
Bot อัตโนมัติรันทุกวัน เช็คทุกเพจ — ถ้ามี comment แจ้ง Master J ก่อนตอบ
📥 INPUT — ได้มาจากไหน
  • Page IDs + tokens ทุกเพจ
    ← จาก config/platforms.json
  • Pages config
    ← จาก Assis_Bot/projects/facebook/config/pages.json
  • คำสั่งรัน
    ← runner.py --project facebook --all
⚙️ PROCESS — ทำอะไร
  • comment_checker วน loop ทุกเพจ ดึง comments ใหม่
  • engagement_stats ดึง impressions/likes/shares
  • token_watcher เช็ค token ยังใช้ได้ไหม
📤 OUTPUT — เอาไปใช้ที่ไหน
  • new_comments.json
    → ถ้ามี comment → แจ้ง Master J รออนุมัติก่อนตอบ
  • daily_stats.json
    → วิเคราะห์ว่า content ไหนได้ผล → ปรับกลยุทธ์
  • token_status.json
    → ถ้า token ใกล้หมด → แจ้งเตือน renew
