## ⚠️ ข้อ 1 — Meta Muse Spark 1.2 / Muse Code

**ถูกหมด ✓** วันที่ 5 ส.ค. · ชื่อรุ่น · สถาปัตยกรรม background agent · และ**ตัวเลขทุกตัวตรง**:

| | Terminal-Bench 2.1 |
|---|---|
| Claude Opus 5 | 86.7% |
| **Muse Spark 1.2** | **82.9%** |
| GPT-5.6 Terra | 81.8% |
| Grok 4.5 | 81.6% |

คำว่า "แซง...ไปเล็กน้อย" ✓ **ถูกจริง** — ห่างแค่ 1.1-1.3 จุด

### 🔴 A. ต้องแก้ — เลขพวกนี้ Meta วัดเอง ไม่ใช่ผลจากกระดานอิสระ

จากเอกสารวิธีวัดที่ Meta เผยแพร่พร้อมการเปิดตัว:

> เลขทั้ง 82.9 และ 86.7 **มาจาก evaluation harness ของ Meta เอง** — ทั้ง Muse Spark 1.2 และ Opus 5 **ยังไม่มี entry ที่ผ่านการยืนยันอิสระบนกระดาน Terminal-Bench ทางการ**
> แต่ละโมเดลถูกรันใน agent product ของตัวเอง: Muse Code สำหรับ Muse · Claude Code สำหรับ Opus · Codex สำหรับ GPT · Grok Build สำหรับ Grok — **คนละสนาม**
> และ Opus 5 ถูกวัดที่ **max effort**

**หลักฐานที่หนักที่สุด:** โมเดลรุ่นก่อนของ Meta เคยได้คะแนน **ต่ำกว่าเลขที่ Meta ประกาศเอง 3.8 จุด** เมื่อทีม Terminal-Bench รันตรวจสอบเอง — และช่วงความเชื่อมั่นที่ผ่านการตรวจนั้น **ไปไม่ถึงเลขที่ Meta เคลม**

**→ เติมประโยคเดียวหลังตาราง/ตัวเลข:**
*"ตัวเลขชุดนี้ Meta เป็นคนวัดเองทั้งหมด แต่ละโมเดลรันในเครื่องมือของค่ายตัวเอง และยังไม่มีใครผ่านการตรวจสอบจากกระดานกลาง — รุ่นก่อนของ Meta เคยได้จริงต่ำกว่าที่ประกาศไว้เกือบ 4 จุดเมื่อทีมกลางรันซ้ำ"*

**ทำไมบังคับ:** เล่าเลขคู่แข่งเรียงลำดับโดยไม่บอกว่าเจ้าของเลขคือคนที่ได้ประโยชน์ = ให้เครดิตเกินหลักฐาน — เป็นบทเรียนเดียวกับที่เราเคยเจอมาแล้ว ("อย่าให้เครดิตเกินหลักฐานแม้เป็นฝั่งเรา")

### 🟡 B. Muse Code ยังเป็น **beta** — ดราฟต์ไม่ได้ระบุ

### 🟡 C. มี benchmark ที่สองที่ผลกลับด้าน (ใส่แล้วโพสน่าเชื่อขึ้นมาก)
**DeepSWE 1.1:** Muse Spark 1.2 ได้ 59.3% = **อันดับ 3** ตามหลัง Opus 5 (65.0%) และ GPT-5.6 Terra (64.8%)
ตอนนี้ดราฟต์เล่าเฉพาะสนามที่ Meta แซง 2 ราย — เติมอันนี้แล้วภาพจะตรงกว่า และอ่านแล้วรู้สึกว่าเราไม่ได้เชียร์ใคร

## ⚠️ ข้อ 2 — OpenAI ปิด ChatGPT Atlas

**ถูก ✓** ปิดจริง **9 ส.ค. 2026** · เปิดตัวฤดูใบไม้ร่วง 2025 · ให้เวลาราว 30 วัน
*(ยืนยันจาก OpenAI Help Center โดยตรง — "Atlas is scheduled to stop working on August 9, 2026")*

### 🟡 D. วันประกาศคือ **9 กรกฎาคม** ไม่ใช่ "ต้นกรกฎาคม"
> "We are giving users an approx. 30 day wind down period. The planned announcement date is **July 9**"

ระบุวันไปเลยแม่นกว่า และทำให้ "ประมาณ 1 เดือน" มีที่มาชัด

### 🔴 E. ยุบเข้า **ChatGPT และ Codex** — ดราฟต์ขาด Codex
> "We're deprecating Atlas and moving browser-based agentic capabilities into **ChatGPT and Codex**"

ดราฟต์เขียนว่ายุบเข้า desktop app + Chrome extension ซึ่งถูกครึ่งเดียว — สองอันนั้นคือ*ที่ที่แนะนำให้ผู้ใช้ไปต่อ* ส่วน*ความสามารถ*ถูกย้ายเข้า ChatGPT **และ Codex**

### 🔴 F. ขาดข้อมูลที่ช่วยคนอ่านได้จริง — และเหลือเวลาแค่ 3 วัน

OpenAI ระบุชัดว่า **ข้อมูลไม่ย้ายให้อัตโนมัติ**:
> "**Bookmarks will not transfer automatically.** Export your Atlas bookmarks before August 9, 2026, then import them into another browser such as Chrome."
> "Open tabs **may not** transfer automatically" · "Browser history **may not** transfer automatically"

**→ เพิ่มย่อหน้าสั้น ๆ:**
*"ใครยังใช้ Atlas อยู่ ต้องรีบ — บุ๊กมาร์ก ประวัติการเข้าเว็บ และแท็บที่เปิดค้าง **จะไม่ย้ายตามไปให้อัตโนมัติ** ต้อง export บุ๊กมาร์กออกมาเองแล้วนำเข้าเบราว์เซอร์อื่นก่อน 9 ส.ค. (ส่วนประวัติแชท ChatGPT เก็บแยกในบัญชี ไม่ได้รับผลกระทบ)"*

นี่คือท่อนที่มีประโยชน์ที่สุดของโพสทั้งชิ้น — โพสวันนี้ 6 ส.ค. เหลือ **3 วัน** พอดี

### 🟡 G. คำโปรยเปิดเรื่องขัดกับข้อ 2
ย่อหน้าแรกเขียนว่า *"3 เรื่องจากวงการ AI ที่เกิดขึ้น**ในสัปดาห์นี้**"* — แต่ Atlas ประกาศตั้งแต่ 9 ก.ค. (เดือนก่อน) สิ่งที่เป็นเรื่อง "สัปดาห์นี้" คือ**เส้นตายที่กำลังจะมาถึง** ไม่ใช่ตัวประกาศ
**→ แก้คำโปรยเป็น** *"3 เรื่องจากวงการ AI ที่กำลังเกิดขึ้นตอนนี้"* หรือระบุในข้อ 2 ว่า *"ประกาศไว้ตั้งแต่ 9 ก.ค. และกำลังจะถึงกำหนดในอีก 3 วัน"*

## ✅ ข้อ 3 — Wonder · TRUE ทั้งข้อ ไม่ต้องแก้

ตรงกับ paper ทุกจุด — `arXiv 2607.26037` **"Wonder: Video World Model Done Better"**
ชื่อรองของ paper คือ *"A Minute-Scale Camera-Steerable Video World at **16 FPS**"* — ตรงกับที่ดราฟต์เขียนคำต่อคำ

| ดราฟต์เขียน | paper |
|---|---|
| Adobe Research + Johns Hopkins | ✓ (Xu, Jiang, Shu, Sunkavalli, Patel, Mei) |
| เผยแพร่ปลาย ก.ค. 2026 | ✓ (arXiv 2607.*) |
| แก้ drift / memory fade / latency growth | ✓ "drifting controls, fading memories, and latency growth" — ตรงคำ |
| แปลงการเคลื่อนกล้องเป็นสัญญาณภาพ | ✓ "turning translation, rotation, and parallax into frame-aligned visual cues" |
| เก็บประวัติเต็มแต่ดึงเฉพาะที่เกี่ยว | ✓ sparse attention memory / sparse retrieval |
| กลั่นเป็นรุ่นเรียลไทม์ | ✓ distills into a real-time student |
| ต่อเนื่องเป็นนาที · 16fps · latency คงที่ | ✓ minute-scale · 16 FPS · "stable real-time latency" |
| ยังเป็นงานวิจัย ไม่ใช่ผลิตภัณฑ์ | ✓ |

ข้อนี้เขียนได้แม่นที่สุดในสามข้อ — ทั้งศัพท์เทคนิคและการแปลเป็นภาษาคนอ่าน

## แก้ A · E · F เป็นอย่างน้อย (D, G ถ้ามีเวลา · B, C ถ้าอยากให้แน่น) → ส่ง v2 + md5 → ผมออก FINAL OK ทันที

ถ้าเวลาไม่พอจริง ๆ **เรียงความสำคัญแบบนี้: F > A > E** — F ช่วยคนอ่านได้จริงและมีเส้นตาย · A กันเราเผลอเป็นกระบอกเสียงให้ตัวเลขที่เจ้าตัววัดเอง · E คือความถูกต้องของข้อเท็จจริง
