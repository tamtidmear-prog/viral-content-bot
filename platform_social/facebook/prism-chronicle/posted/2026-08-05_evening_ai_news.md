📉 หนึ่ง — OpenAI ลดราคา แลกกับผู้ใช้ทะลุพันล้าน

ปลายเดือนกรกฎาคมที่ผ่านมา OpenAI ประกาศลดราคาโมเดล GPT-5.6 Luna ลงถึง 80% — จาก 1 ดอลลาร์ เหลือ 0.20 ดอลลาร์ต่อ 1 ล้าน input token และจาก 6 ดอลลาร์ เหลือ 1.20 ดอลลาร์ต่อ 1 ล้าน output token ส่วนรุ่น Terra ลดลง 20% (จาก 2.50/15 ดอลลาร์ เหลือ 2/12 ดอลลาร์) เฉพาะรุ่นเรือธง Sol ที่ยังคงราคาเดิม

พร้อมกันนั้น OpenAI เปิดเผยว่าตอนนี้มีผู้ใช้งานโมเดลของบริษัทมากกว่า 1,000 ล้านคน และมีธุรกิจที่ใช้งานมากกว่า 2 ล้านราย บริษัทไม่ได้ระบุชัดว่าตัวเลขนี้นับแบบรายสัปดาห์หรือรายเดือน แต่จากตัวเลขก่อนหน้าที่เคยประกาศว่า ChatGPT มีผู้ใช้รายสัปดาห์เกิน 900 ล้านคน ก็มีแนวโน้มว่าตัวเลขล่าสุดนี้จะยังนับแบบรายสัปดาห์เช่นเดิม

ทำไมเรื่องนี้สำคัญ: OpenAI อธิบายว่าการลดราคามาจากการทำ AI ให้เข้าถึงง่ายขึ้นและ infrastructure ที่มีประสิทธิภาพขึ้น — แต่จังหวะเวลาชวนให้มองอีกมุม: GPT-5.6 เพิ่งเปิดตัว 9 กรกฎาคม แล้วลดราคา 80% ในวันที่ 30 กรกฎาคม ห่างกันแค่ 3 สัปดาห์ ขณะที่โมเดลจากจีนกินส่วนแบ่งการใช้งานฝั่งองค์กรในสหรัฐฯ ไปแล้วราว 46% สื่อหลายสำนักจึงอ่านว่านี่คือสงครามราคา มากกว่าการส่งต่อต้นทุนที่ถูกลง แม้แต่หลักพันล้านผู้ใช้เองก็มาช้ากว่าที่บริษัทคาดไว้ตั้งแต่ต้นปี ด้วยเหตุผลเดียวกันคือการแข่งขัน — และเมื่อ "คนใช้ AI" ทะลุหลักพันล้านคนแล้ว มันไม่ใช่เทคโนโลยีเฉพาะกลุ่มอีกต่อไป แต่กลายเป็นโครงสร้างพื้นฐานที่คนทั่วไปพึ่งพาในชีวิตประจำวันจริง ๆ

🔒 สอง — เมื่อ AI ยิ่งเยอะ ความเสี่ยงด้านความปลอดภัยก็ยิ่งต้องจัดการ

วันที่ 4 สิงหาคมที่ผ่านมา บริษัท Anaconda ประกาศเข้าซื้อกิจการ Enkrypt AI สตาร์ทอัพด้านความปลอดภัย AI โดยไม่เปิดเผยมูลค่าดีล การซื้อครั้งนี้จะนำระบบ red-teaming (การจำลองโจมตีเพื่อทดสอบจุดอ่อน) ที่ครอบคลุมมากกว่า 300 ประเภทการโจมตี ระบบ guardrail ตอน runtime และระบบตรวจสอบมาตรฐาน NIST กับ EU AI Act มารวมเข้ากับแพลตฟอร์มของ Anaconda

ตัวเลขที่น่าสนใจคือ Enkrypt AI สแกนเครื่องมือ AI ไปกว่า 268,000 ตัว บน MCP server กว่า 25,000 แห่ง ภายในสองเดือนก่อนประกาศดีล และพบช่องโหว่มากกว่า 143,000 จุด ซึ่งกระทบกับ MCP server ถึง 73% ของทั้งหมดที่สแกน (ดีลนี้เป็นดีลที่สองติดกันของ Anaconda ในรอบไม่ถึงสองเดือน ต่อจากการซื้อ Kilo Code เมื่อกรกฎาคม)

ทำไมเรื่องนี้สำคัญ: MCP (Model Context Protocol) คือมาตรฐานที่ทำให้ AI agent เชื่อมต่อกับเครื่องมือภายนอกได้ — ยิ่งองค์กรใช้ AI agent เชื่อมกับระบบข้างนอกมากขึ้นเท่าไหร่ พื้นที่เสี่ยงก็ยิ่งกว้างขึ้นเท่านั้น ตัวเลข 73% ของ MCP server ที่มีช่องโหว่ เป็นสัญญาณเตือนว่าฝั่ง security ต้องโตให้ทันฝั่ง capability ไม่ใช่ตามหลัง

⚖️ สาม — ใครรับผิดชอบ เมื่อ AI agent ช้อปปิ้งแทนเรา

ศาลอุทธรณ์สหรัฐฯ เขตที่ 9 (Ninth Circuit) มีคำตัดสินพลิกคำสั่งห้ามชั่วคราวที่ Amazon เคยได้จากศาลชั้นต้นเมื่อมีนาคม 2026 ที่สั่งห้าม Perplexity ใช้ AI shopping agent ชื่อ Comet ทำการซื้อของบน Amazon ให้ผู้ใช้

คดีนี้เริ่มจาก Amazon ฟ้อง Perplexity ปลายปี 2025 กล่าวหาว่า AI shopping bot ของ Comet เข้าถึงบัญชีลูกค้าที่มีรหัสผ่านป้องกันไว้โดยไม่ได้รับอนุญาต ภายใต้กฎหมาย Computer Fraud and Abuse Act (CFAA) แต่ศาลอุทธรณ์ตัดสินว่า Amazon ไม่น่าจะพิสูจน์ได้ว่า Perplexity ละเมิดกฎหมายนี้จริง เพราะผู้ที่ "เข้าถึง" ระบบของ Amazon คือตัวผู้ใช้เองที่สั่งให้ browser ทำงาน ไม่ใช่ Perplexity โดยตรง

คำตัดสินนี้ทำให้ Perplexity กลับมาใช้งาน AI shopping agent บน Amazon ได้ต่อระหว่างที่คดีหลักยังดำเนินอยู่ต่อไป

ทำไมเรื่องนี้สำคัญ: นี่คือหนึ่งในคดีแรก ๆ ที่จะวางบรรทัดฐานว่า เมื่อ AI agent ทำงานแทนเรา ใครคือคนที่ "กระทำ" ทางกฎหมาย — ตัว AI เอง บริษัทที่สร้างมัน หรือคนที่สั่งงานมัน คำตอบของคำถามนี้จะกำหนดว่าต่อไปเราจะไว้ใจให้ AI agent ทำธุรกรรมแทนเราได้มากแค่ไหน และแพลตฟอร์มต่าง ๆ จะเปิดหรือปิดประตูให้ AI agent เข้ามาได้อย่างไร
